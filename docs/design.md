# 设计说明

这份文档记录**为什么这样建**，而不是建了什么（那看 README）。改架构之前先读它，
因为下面每条取舍都是被具体问题逼出来的，不是风格偏好。

## 1. 知识层 (Clause) 与规则层 (Rule) 必须分开

同一条条文会被两类消费者用，而它们要的东西冲突：

- 人/agent 要**原文和解读**，才能理解"为什么 8~10mm"、"为什么取消 0.35"；
- 程序要**一个能比较的值**，比如 `min_print_mm: 2.5`。

混成一个字段，就必然要二选一：要么存了人话但程序读不懂，要么存了值但人看不懂依据。

所以每条 Clause 存 `verbatim` / `interpret` / `machine` 三段，Rule 用 `cite` 指回
`clause_id`。`kb verify` 会检查这个指向真实存在——**规则和条文脱钩时直接失败**，
而不是悄悄产出一份看起来很有依据的报告。

这带来一个约束：一条 Rule 没有规范依据时，必须显式写 `cite: null` 并在报告里
标注"无直接规范条号"。允许没有依据，但不允许假装有依据。

## 2. severity 由条文用词决定，不由后果决定

「应 / 不应 / 必须 / 不得」→ `error`，「宜 / 不宜」→ `warning`。

理由是：这个工具最大的风险不是漏报，而是**把推荐当强制**。GB/T 50001 §13.0.2
说图层名"宜"用分级格式，§13.0.1 说"不应"同时用汉字和英文字母——两条相邻，
强度相反。如果都报 error，用户第一次用完就会把工具删掉；如果都报 warning，
真正违规的地方会被淹没。

`tests/test_rules.py::test_severity_of_cite_matches_wording` 守着这条：
条文含强制用词且不含"宜"时，`severity_hint` 必须是 error。条文换版本时它会拦一下。

**已知例外**：《建筑工程设计文件编制深度规定》的条文是列举式（"平面图。1 ……；"），
没有"应/宜"用词。这类条文的级别不能从用词推出，只能按"缺了会不会被施工图审查退图"
定，并在 `source_note` 里写明这个推理链。这是唯一允许偏离用词规则的情况，
且必须在卡片里显式说明。

## 3. 级别以 `data/rules` 为准，代码只给默认值

`run_rules()` 会用 `rule.severity` 覆盖 check 函数返回的 severity。

好处：调级别只改 YAML，不用改代码；也不会出现"YAML 写 warning、函数里写 info"
的两处不一致（这种不一致迟早会让人怀疑整份报告）。

代价：check 函数返回的 severity 实际上被忽略，看起来像死代码。所以函数里保留的
severity 只是给"脱离 YAML 直接调用函数"的场景兜底，注释里已说明。

## 4. 尺寸一律换算到打印图纸

规范里的 2.5mm 字高、8~10mm 轴号圆、0.5/0.7/1.0/1.4mm 线宽，**全部是打印成品
图纸上的尺寸**；模型空间是 1:1 的。所以每个几何判定都要除以出图比例。

这就是 `--scale` 是必填语义的原因，也是"图纸未注比例"（R-DIM-002）被判为
warning 的原因——比例缺失时，所有几何结论都建立在用户传进来的假设值上。

## 5. 同类问题合并成一条 Finding

一份 200 张图的图纸集，如果图层都叫"外墙"，逐条报会产出几百条一模一样的结论。
所以 check 函数返回的是 `count + sample`，报告里合并成一条，附前几个样本。

代价：单条 Finding 不再对应单个实体。但 `handle` 保留第一个实例的位置，
agent 拿到可以定位到起点；要枚举全部时需要 `--format json` 的 `sample` 字段。

## 6. 制图标准与深度规定是两回事

- **GB/T 50001** 管「画得对不对」：线宽、字高、轴号方向、图层命名。
- **《深度规定》** 管「该有的内容有没有」：尺寸、标高、比例、指北针。

一张图可以一处制图错误都没有，却因为完全没标尺寸而无法施工。如果把这两类
判定混成一个"合规性"分数，agent 就会在缺尺寸时还自信地说"符合规范"。

所以数据文件按**依据所属文件**分家（`gbt50001-2017.yaml` / `sjd-2016.yaml`），
报告里也分开引用。以后加 GB 55xxx 强条时同理。

## 7. 图片表格一律留空

表 4.0.1（线宽组）、表 5.0.2（字高）、附录 B（常用图层名）在来源站点上是图片，
没有可靠的文本版本。

**不猜**。留空并在报告里说明"依据待补"，比录一个看起来很像但错的数值好得多——
错误的标准数值会被下游当真，而空白至少诚实。

## 8. 检测手段的不可靠性必须写在 message 里

R-DIM-001 只数 `DIMENSION` 实体。如果用户用 `LINE` + `TEXT` 手工拼尺寸线，
就会误报。R-DIM-002 只做文字匹配，比例写在布局视口或标题栏块里也会误报。

这些已知的误报路径**直接写进报告的 message**，而不是藏在文档里。理由：用户看到的
是报告，如果报告不承认自己的局限，用户会用错误的信心去改图。

同理，反向的漏检（有标注但标错了）不在任何规则的范围内，这一点也要说清。
