# 设计说明

这份文档记录**为什么这样建**，而不是建了什么（那看 README）。改架构之前先读它，
因为下面每条取舍都是被具体问题逼出来的，不是风格偏好。

## 1. 知识层 (Clause) 与规则层 (Rule) 必须分开

同一条条文会被两类消费者用，而它们要的东西冲突：

- 人/agent 要**原文和解读**，才能理解"为什么 8~10mm"、"为什么取消 0.35"；
- 程序要**一个能比较的值**，比如 `min_print_mm: 2.5`。

混成一个字段，就必然要二选一：要么存了人话但程序读不懂，要么存了值但人看不懂依据。

所以每条 Clause 存 `verbatim` / `interpret` / `machine` 三段，Rule 用 `cite` 指回
`clause_id`。`kb verify` 会检查这个指向真实存在——**规则和条文脱钩时直接失败**，
而不是悄悄产出一份看起来很有依据的报告。

这带来一个约束：一条 Rule 没有规范依据时，必须显式写 `cite: null` 并在报告里
标注"无直接规范条号"。允许没有依据，但不允许假装有依据。

## 2. severity 由条文用词决定，不由后果决定

「应 / 不应 / 必须 / 不得」→ `error`，「宜 / 不宜」→ `warning`。

理由是：这个工具最大的风险不是漏报，而是**把推荐当强制**。GB/T 50001 §13.0.2
说图层名"宜"用分级格式，§13.0.1 说"不应"同时用汉字和英文字母——两条相邻，
强度相反。如果都报 error，用户第一次用完就会把工具删掉；如果都报 warning，
真正违规的地方会被淹没。

`tests/test_rules.py::test_severity_of_cite_matches_wording` 守着这条：
条文含强制用词且不含"宜"时，`severity_hint` 必须是 error。条文换版本时它会拦一下。

**已知例外**：《建筑工程设计文件编制深度规定》的条文是列举式（"平面图。1 ……；"），
没有"应/宜"用词。这类条文的级别不能从用词推出，只能按"缺了会不会被施工图审查退图"
定，并在 `source_note` 里写明这个推理链。这是唯一允许偏离用词规则的情况，
且必须在卡片里显式说明。

## 3. 级别以 `data/rules` 为准，代码只给默认值

`run_rules()` 会用 `rule.severity` 覆盖 check 函数返回的 severity。

好处：调级别只改 YAML，不用改代码；也不会出现"YAML 写 warning、函数里写 info"
的两处不一致（这种不一致迟早会让人怀疑整份报告）。

代价：check 函数返回的 severity 实际上被忽略，看起来像死代码。所以函数里保留的
severity 只是给"脱离 YAML 直接调用函数"的场景兜底，注释里已说明。

## 4. 尺寸一律换算到打印图纸

规范里的 2.5mm 字高、8~10mm 轴号圆、0.5/0.7/1.0/1.4mm 线宽，**全部是打印成品
图纸上的尺寸**；模型空间是 1:1 的。所以每个几何判定都要除以出图比例。

这就是 `--scale` 是必填语义的原因，也是"图纸未注比例"（R-DIM-002）被判为
warning 的原因——比例缺失时，所有几何结论都建立在用户传进来的假设值上。

## 5. 同类问题合并成一条 Finding

一份 200 张图的图纸集，如果图层都叫"外墙"，逐条报会产出几百条一模一样的结论。
所以 check 函数返回的是 `count + sample`，报告里合并成一条，附前几个样本。

代价：单条 Finding 不再对应单个实体。但 `handle` 保留第一个实例的位置，
agent 拿到可以定位到起点；要枚举全部时需要 `--format json` 的 `sample` 字段。

## 6. 制图标准与深度规定是两回事

- **GB/T 50001** 管「画得对不对」：线宽、字高、轴号方向、图层命名。
- **《深度规定》** 管「该有的内容有没有」：尺寸、标高、比例、指北针。

一张图可以一处制图错误都没有，却因为完全没标尺寸而无法施工。如果把这两类
判定混成一个"合规性"分数，agent 就会在缺尺寸时还自信地说"符合规范"。

所以数据文件按**依据所属文件**分家（`gbt50001-2017.yaml` / `sjd-2016.yaml`），
报告里也分开引用。以后加 GB 55xxx 强条时同理。

## 7. 图片表格一律留空

表 4.0.1（线宽组）、表 5.0.2（字高）、附录 B（常用图层名）在来源站点上是图片，
没有可靠的文本版本。

**不猜**。留空并在报告里说明"依据待补"，比录一个看起来很像但错的数值好得多——
错误的标准数值会被下游当真，而空白至少诚实。

## 8. 检测手段的不可靠性必须写在 message 里

R-DIM-001 只数 `DIMENSION` 实体。如果用户用 `LINE` + `TEXT` 手工拼尺寸线，
就会误报。R-DIM-002 只做文字匹配，比例写在布局视口或标题栏块里也会误报。

这些已知的误报路径**直接写进报告的 message**，而不是藏在文档里。理由：用户看到的
是报告，如果报告不承认自己的局限，用户会用错误的信心去改图。

同理，反向的漏检（有标注但标错了）不在任何规则的范围内，这一点也要说清。

## 9. 每条结论都要能定位到实体

`handle=3D2 @ (4508, 12169)`，而不只是"这图有 8 处字高不够"。

因为下游是 agent：它拿到 handle 可以直接去改那个实体，改完再跑一遍，形成闭环。
只报数量不报位置，人和 agent 都只能干看着。

## 10. 能不能自动判，由条文自己声明

不是每条规范都判得了。「踏步宽度不应小于 0.26m」可以判，「楼梯间应能天然采光和自然通风」
判不了。所以每条条文可以带一个 `machine.checkable`：

| 值 | 含义 |
|---|---|
| `full` | 图纸信息齐全，检测手段可靠，可以自动判 |
| `partial` | 能判，但缺前提或手段会误报（如尺寸是 LINE+TEXT 手拼的） |
| `none` | 判不了，只供检索 |
| 不写 | 还没评估过 |

`kb verify` 强制：**任何被规则引用的条文，必须声明 `checkable`，且不能是 `none`**。
防的是"规则声称依据某条规范，而那条规范从没表示过自己能判"——那种规则其实是写规则的
人自己编的判据挂了个条号。

**611 条没声明的保持不写，不批量标 `none`**。`none` 的语义是"评估过、判不了"，
批量标等于造假数据，这个字段就废了。

`kb coverage` 打印当前覆盖率：17 / 626（3%）。自动判定本来就只覆盖一小片——数值、位置、
命名这类图上信息完整的东西。剩下的绝大多数只能检索。

## 11. 两档：先看得懂"表达"，再看懂"尺度"

前十条判的是「画得对不对、该有的有没有」，只看图层名、文字、线宽，不需要知道墙在哪。
但「卧室不应小于 5m²」得先知道哪里是房间、房间多大。

`--level strict` 才做几何识别，因为它对图纸有前提：

| 要求 | 为什么 |
|---|---|
| 墙用 MLINE 画 | 单根线分不出墙厚，也围不成房间 |
| 墙在 `外墙` / `内墙` 图层 | 图层名是唯一能区分墙和其他线的线索 |
| 门窗在 `门窗` 图层 | 洞口要算进外墙轮廓，否则外轮廓是断的 |
| 房间里有文字写用途 | 不知道是卧室还是储藏室，面积就没法判 |

不满足就降级 `basic`，并在报告里写明「本档未做几何识别」，而不是静默给出错误结论。

## 12. 几何识别的三处非常规做法

**内缩半个墙厚**：面积不能直接取多边形。墙中心线围出的是轴线面积，规范要的是使用面积。
3.0×1.5m 的房间轴线 4.50m²、净面积只有 3.64m²，差 19%，不内缩会把不合格判成合格。

**墙厚 = `scale_factor` × 样式里各线的 offset 跨度**，不是 `scale_factor` 本身。
1.dxf 的 `WALL` 样式 offsets 是 `[10, -5]`，跨度 15，`scale_factor` 20，所以墙厚 300mm。
早期版本直接把 20 当墙厚，面积全错。

**出入线必须一起量化**：`unary_union` 不会切开坐标差 1e-12 的 T 型交点，
`polygonize` 又用精确相等判环闭合。所以要先 `set_precision(..., GRID_MM)` 再 union，
`GRID_MM` 取 1.0mm——`_snap` 的聚类平均让同一交点在不同线上差 0.01~0.02mm，
0.01 的网格量化后仍差一格。

## 13. 门窗判断不出来时，说不知道

图上"门"和"窗"不是两种实体，都是墙上的一个洞。要分开只能靠周边线索，按可靠性排序：

| 线索 | 例子 | 可靠性 |
|---|---|---|
| 图层名 | 门画在 `门` 层、窗画在 `窗` 层 | 高 |
| 多线样式名 | `DOOR` / `WINDOW` | 高 |
| 块名 | 洞口上盖了 `门` 块 | 高 |
| 门扇弧线 | 带 bulge 的多段线、半径等于洞口宽 | 高（门的强特征） |
| 编号文字 | `M1`（门）/ `C1`（窗） | 中 |
| 宽度 | 900mm 像门，1500mm 像窗 | 低，只作冲突提示 |

`门窗` 这种合并命名的图层**不算线索**——"门"和"窗"两头都含，据它定性会把整张图的洞口
一次判成同一种。

**样式名被复用时也不算数**：同一图层所有洞口共用 `WINDOW` 样式、宽度却从 900 跨到 2400mm，
说明画图时是复制一条多线改的，样式名只是继承下来的。按它判会把门判成窗，而且判错的
还是「通过」——把 1800mm 的门当窗之后，就没人去核它的门洞净宽了。**假阴性比"判不出来"
危险得多**，所以这类洞口一律降级 `unknown`。

全都拿不到时说 `unknown`，并告诉用户缺什么、补上哪一样就能继续判。

## 14. 缺画比画错更危险

一张图完全没有 error，也可能是"该有的一个都没画"。最初只查"画错了什么"，
直到看见一张全绿的报告：外轮廓上一个门洞都没有。

`R-OPEN-003` 因此不是判"门画得对不对"，而是判"有没有一扇门通到室外"。同理，
空的"楼梯"图层不是模板残留，是还没画。

这条是外部审查工具教出来的：它抓到「全图没有一扇通向室外的门」「楼梯未画」两条，
都是纯几何规则判不出来的。**判错可以改，判不了会让人以为没问题。**
