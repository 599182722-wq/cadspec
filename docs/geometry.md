# 几何识别：从一张真实图纸学到了什么

这篇记录 `scripts/probe_rooms.py` 在 `D:\dsh\cad\1.dxf` 上的探查结果。
目的是回答一个问题：**这张图上的房间，能不能被程序自己数出来。**

结论是能，而且比预想的干净。下面是从数据里读出来的三件事。

## 一、墙的中心线是精确的

47 条 MLINE（外墙 12、门窗 12、内墙 23）的顶点，端点之间的误差中位数是 0。
只有一处偏差 14.8mm（`(5783.5, 14004.7)` 那条外墙的起点），20mm 容差吸附后全部对齐。

这意味着不需要做图像识别，也不需要猜测墙在哪里——作者画图时是精确的，
程序要做的是把断开的线段接起来。

## 二、门窗实体正好填在外墙的缺口上

外墙在每处洞口断开，而 `门窗` 图层的 12 条 MLINE 恰好把那 12 个缺口补满，
端点坐标逐点吻合。所以：

```
外墙 + 门窗 → 一个闭合多边形 → 182.09 m² / 15600 × 17400 mm
```

洞口宽度可以直接量，不需要单独识别：

```
900, 900, 1200, 1200, 1500, 1800, 1800, 1800, 1800, 1800, 2400, 2400
```

全是整百的数，是设计时定的洞口尺寸。900 和 1200 是门，1500 以上是窗——
但这个判断目前靠尺寸猜，不能当作依据，因为窗也可能做 900。

## 三、内墙在门洞处断开，补回去就是房间

内墙有 23 条，其中不少是同一条墙被门洞切成两段，例如：

```
(5633.9, 7669.9) → (5633.9, 8469.9)   缺口 800mm
(12533.9, 15709.9) → (12533.9, 16409.9)  缺口 700mm
```

这些缺口**没有**被门实体填充（这张图的 INSERT 是 0，没有门窗块）。
把同层、正交、间距 2m 以内的端点两两连起来，再跑一次多边形化：

```
10 个多边形，面积合计 182.09 m²
```

和外面那个大轮廓**完全相等**——说明 10 个房间正好铺满整层，没有剩余、没有重叠。
这正是分割成功的样子。

## 这对规则意味着什么

拿到房间多边形之后，下面这些检查就从「做不到」变成「写个函数」：

| 判据 | 来源 | 需要的量 |
|---|---|---|
| 卧室面积 ≥ 5 m² | GB 55038 4.1.2 | 房间面积 |
| 兼起居室卧室 ≥ 9 m² | GB 55038 4.1.2 | 房间面积 |
| 卧室短边 ≥ 1.80 m | GB 55038 4.1.2 | 最小外接矩形短边 |
| 过道净宽 ≥ 1.10 / 1.00 / 0.90 m | GB 55038 4.1.6 | 走廊多边形短边 |
| 门洞净宽 ≥ 0.90 / 0.80 / 0.70 m | GB 55038 4.1.7 | 洞口段长 |

还差一步：**房间和用途要对上**。「5.67 m²、2100×2700」这个多边形，是卧室还是卫生间？
规范对两者的面积要求完全不同。这张图里没有房间名称标注（没有文字写在房间内部），
所以第一版只能报「有一个 5.67 m² 的房间，短边 2.10m」，不能报「卧室面积不足」。

用途信息有三种可能来源，可靠性依次下降：
1. 房间内部或附近有文字（`家具`/`文字` 图层）
2. 有家具块，能推断功能
3. 按面积和位置猜

第一版只做第 1 种，认不出来就说认不出来。

## 两档设计

**宽松档**（不做任何要求）：只跑现在这 15 条规则，任何 DXF 都能跑，报告头部写明
「本档未做几何识别，尺寸类条文不在检查范围」。

**严格档**（要求画图约定）：需要墙在 `外墙`/`内墙` 图层且用 MLINE、门窗在 `门窗` 图层、
房间内部有文字或块。满足约定才启用房间识别与尺寸类规则，报告里同样写明本档覆盖了什么。

两档共用同一套引擎，区别只在「要不要走几何识别」，以及报告里那句覆盖说明。

## 房间用途怎么认（还没做，先把方案定下来）

房间多边形出来之后，还差一步才能判「卧室面积够不够」：得知道这个多边形是什么房间。
规范对卧室和卫生间的要求完全不同，认错用途比不判更糟。

**首选信号：块。** 卫生间有坐便器、洗手盆、淋浴间，厨房有灶台、水槽，卧室有床。
如果这些是块（INSERT），块名通常就写着用途。这是最可靠的来源，因为块是设计者主动放的，
不是从形状反推的。识别逻辑是：遍历房间内的 INSERT，把块名归一成功能类别，
按「出现了几类特征设备」判用途——卫生间要有洁具，厨房要有灶台加洗涤，
单个块不足以下结论。

块名的现实问题：可能是中文（`马桶`）、英文（`TOILET`）、拼音缩写（`MT`）、
纯编号（`BLOCK001`）、或匿名块（`*U12`）。所以需要一张别名映射表，
放在 `data/blocks/names.yaml`，开源之后别人可以往里加自己画图时的叫法。
认不出的块名不猜。

**这张图用不了这条路**：`1.dxf` 的 INSERT 是 0，块定义只有 `_ArchTick`（标注箭头）
和 `*D2`–`*D7`（标注样式块），没有任何家具块。家具图层只有 4 条 LINE，
组成两个 L 形（1800×2200、1800×2500），从尺寸看像床或衣柜的简化画法，
但没有名字，认不出是什么。

**次选信号：房间内的文字。** 有些图会在房间中间标「卧室」「厨房」。
拿文字插入点做点在多边形内判断即可，实现成本低。这张图的文字全在 `高差线` 图层，
内容是标高数值和门窗编号，没有房间名。

**都没有就不判。** 报告里写「房间 5.67 m²，短边 2.10m，用途未识别」——
这个信息对人类已经够用，agent 可以把选择权交给用户。

**最后是手工覆盖。** 提供 sidecar 文件，让人直接写：

```yaml
# 1.rooms.yaml
"11484,15450": 卫生间
"15384,16060": 起居室
```

按房间中心点坐标匹配。这比任何自动识别都可靠，代价是要人写一遍。
