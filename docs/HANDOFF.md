# 交接：接手这个项目先读这一页

写这份文档的原因：项目做了很久，细节散在几十次对话里。新开一个会话、换一个人接手时，
读这一页能在五分钟内知道「这是什么、做到哪了、下一步做什么、哪些线不能踩」。

---

## 一、这是什么

`cadspec` 是一个中国建筑规范知识库 + DXF 合规校验器。

给它一张 `.dxf` 平面图，它按国标逐条检查，报出：哪里不符合、依据第几条、原文什么意思、
错在图纸的哪个实体上。

**最终目标不是"审图工具"，是"画图时的规范助手"**——让 AI 画 CAD 时会主动来问
「这个卧室最小要多大」「这个门洞该留多宽」，而不是画完了被挑错。

## 五、不能踩的线

这几条是反复讨论后定下来的，改之前先想清楚为什么当初这么定：

- **零依赖底线**：除 `ezdxf` + `pyyaml` 不加依赖。**不做向量检索**，关键词 + 同义词表够用。
  理由是这东西要能被学生 `pip install` 下来直接用。
- **完全离线**：不联网、不上传图纸、不要 API key。图纸是别人的成果。
- **不收图集**：国家建筑标准设计图集（22G101 类）有著作权，仓库里永远不放 PDF／截图／扫描件。
  只放条文的结构化转述 + 官方链接。
- **不做双线墙识别**：那是通用 CAD 解析器的活。改走「体检告诉人改哪几处」这条路。
- **exe 不进仓库**：可执行文件不该有 commit 历史，45MB 会让 clone 变慢。README 里写了自行打包命令。
- **不为让某张图变绿而加规则**：规则只照规范写，图不合格就报不合格。
- **级别一律以 `data/rules/*.yaml` 为准**，`check` 函数里的 severity 只是默认值。
- **`cite` 必须指向真实条文**，`validate_kb` 会拦。规则不许自己编依据挂个条号。

## 六、环境与踩过的坑

**环境**：Python 由 `uv` 管理（直接 `pip install` 会被 PEP 668 拦）。项目 venv 在
`.venv`，命令是 `.venv\Scripts\cadspec.exe`。git 用便携版 `D:\dsh\tools\mingit\cmd\git.exe`，
仓库配了代理 `http://127.0.0.1:7897`。

**踩过并修复的坑**（都写了测试，不要重犯）：

- **Windows 控制台编码**：英文系统代码页是 1252，`print` 中文会抛 `UnicodeEncodeError`。
  所有入口都要先调 `cadspec.console.fix_console()`。
- **PowerShell 管道给 JSON 加 BOM**：`json.load` 会报 `Unexpected UTF-8 BOM`。
  agent 消费 JSON 一律用 `-o` 写文件，不要走管道。
- **YAML 里 ASCII 冒号加空格**会把 plain scalar 截断：含 `:` 的字段一律用块标量 `|`。
- **MLINE 的 API**：顶点在 `e.vertices[i].location`，样式名是 `style_name`，墙厚是
  `scale_factor × 样式 offset 跨度`（不是 `scale_factor` 本身）。
- **几何 bug 不会在单张图上暴露**：补图前后房间数变化是最灵敏的探针。
  `GRID_MM` 必须是 1.0，太细的量化会让 `polygonize` 判不出闭合。
- **PyInstaller 打包后相对导入会失败**：入口脚本里用绝对导入 `from cadspec import ...`。

## 七、这个项目的判断方式

留给接手人的一条经验：**遇到"要不要加功能"的分歧时，问三个问题**——

1. 这个功能是在补"画之前不知道该画多少"，还是在补"画完被挑错"？优先前者。
2. 它需要新依赖吗？需要就先怀疑。
3. 没有它，闭环还能转吗？能转就往后放。

条文从 626 补到 3600 不会让闭环更好用；让 agent 会问一句"厨房最小多大"会。
